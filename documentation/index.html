AutoRecon / Corporate Partners Reconciliation System

System Overview

AutoRecon compares uploaded KPX Web Data and Corporate Partner Data transactions. It helps operations teams identify matched, mismatched, duplicate, and locked transactions before reports or reconciliation outputs are used.

Primary purpose Compare KPX Web Data against Partner Data
Key outcomes Matched, not matched, duplicate, and locked results
Runtime PHP + MySQL on XAMPP localhost

Main Modules

KPX Web Data Uploader

Accepts KPX-side Excel files, previews rows, validates pending data, and stores accepted transactions.

Partner Data Uploader

Accepts partner-side Excel files and applies partner-specific checks before database insertion.

Web Data Report

Lists KPX Web Data transactions with date and corporate partner filters, detail modals, and Excel export.

Partner Data Report

Lists partner transactions with filters, detail viewing, export actions, and scrollable result tables.

Process Recon

Runs reconciliation by partner and date range, then displays matched, not matched, and duplicate results.

Locked Reconciliation Dates

Blocks uploads and repeat reconciliation for dates that were already locked after matching.

Legacy ID Maintenance

Maintains branch Legacy ID values used by MONEYGRAM upload validation and branch mapping.

Users / Admin

Manages application users, profile controls, account status, and admin-only operational actions.

Dashboard / Home

Landing workspace for upload, reporting, reconciliation, maintenance, and administration sections.

Upload Workflow

  1. Select a Corporate Partner from the upload section.
  2. AutoRecon auto-fills the Partner ID where the partner profile supports it.
  3. Drag and drop an Excel file or browse for the file manually.
  4. Preview the uploaded file before committing it to storage.
  5. Delete the pending file if the preview is wrong or the wrong partner was selected.
  6. Upload the file after confirming the preview.
  7. Validate locked reconciliation dates before insert.
  8. Validate duplicates so the same transaction set is not inserted twice.
  9. For MONEYGRAM, validate Legacy ID data against branch master data.
  10. Show success, error, and warning modals through the application notice layer.
Upload guard sequence:
1. Confirm selected corporate partner
2. Parse Excel file with PhpSpreadsheet
3. Preview normalized rows
4. Reject rows inside locked dates
5. Reject duplicate transactions
6. Apply partner-specific validation
7. Insert accepted rows with prepared statements

Reconciliation Workflow

  1. Select a Corporate Partner.
  2. Select Start Date and End Date.
  3. Click Start Reconcile.
  4. Check locked dates before processing the range.
  5. For MONEYGRAM, show the MONEYGRAM Reconciliation Details modal when reviewing transactions.
  6. Display matched, not matched, and duplicate results.
  7. Lock matched transactions after confirmed reconciliation.
  8. Allow admin users to unlock locked dates when correction or reprocessing is required.
Matching result categories:
- Matched: partner and KPX web records share the expected key
- Not matched: one side has no corresponding transaction
- Duplicate: repeated candidate records are detected
- Locked: transaction date is protected from upload or reconciliation

Locked Date Logic

Locked dates protect reconciled transaction days from accidental re-upload or repeat reconciliation. A locked date should be treated as read-only until an authorized admin unlocks it.

  • Locked dates cannot be uploaded again.
  • Locked dates cannot be reconciled again.
  • The View Locked Dates modal shows locked partner/date records.
  • The Unlock button is available for authorized admin correction flows.
  • Locked-date notices should appear before work begins, not after partial processing.
Expected lock lookup:
SELECT corporate_partner, transaction_date
FROM filerecondb.locked_reconciliation_dates
WHERE corporate_partner = ?
  AND transaction_date BETWEEN ? AND ?;

MONEYGRAM Rules

MONEYGRAM reconciliation uses partner data from moneygram_partner_data and KPX web data from ml_web_data. The core matching key is the partner reference ID against the KPX CCREf number.

Area Rule
Partner Data table filerecondb.moneygram_partner_data
KPX Web Data table filerecondb.ml_web_data
Matching key moneygram_partner_data.reference_id = ml_web_data.ccref_no
Legacy ID validation Check masterdata.branch_profile.legacyid_moneygram.
Branch mapping Use maintained Legacy ID values to map MONEYGRAM rows back to branch records. 
SELECT p.reference_id, w.ccref_no
FROM filerecondb.moneygram_partner_data p
JOIN filerecondb.ml_web_data w
  ON p.reference_id = w.ccref_no
WHERE w.transaction_date BETWEEN ? AND ?;

Reports

Reports provide transaction review outside the upload and reconciliation actions. They should remain filterable and exportable without changing source values.

  • KPX Web Data transactions report.
  • Partner Data transactions report.
  • Date filters for transaction date ranges.
  • Corporate Partner filters.
  • Export Excel action for reviewed data.
  • View transaction details modal for row-level inspection.

UI / UX Notes

  • Sidebar navigation is the primary module switcher.
  • Light and dark themes should keep text readable and controls discoverable.
  • Seasonal theme behavior should not hide operational notices or actions.
  • Processing modals should appear while uploads, exports, or reconciliation jobs are running.
  • SweetAlert notices communicate success, error, warning, and confirmation states.
  • Pending upload warnings should prevent accidental partner or file changes.
  • Large tables need stable scrolling, usable spacing, and visible column context.

Database Reference

Common tables referenced by AutoRecon workflows:

Table Purpose
filerecondb.ml_web_data KPX Web Data transaction storage used by reports and reconciliation.
filerecondb.moneygram_partner_data MONEYGRAM partner upload storage and reconciliation source.
filerecondb.moneygram_sendout_data MONEYGRAM sendout-related transaction data when used by the partner flow.
masterdata.branch_profile Branch master data, including legacyid_moneygram for validation and mapping.
filerecondb.locked_reconciliation_dates Locked corporate partner/date records that block uploads and repeat reconciliation. 
CREATE TABLE filerecondb.locked_reconciliation_dates (
    id INT AUTO_INCREMENT PRIMARY KEY,
    corporate_partner VARCHAR(100) NOT NULL,
    transaction_date DATE NOT NULL,
    locked_by VARCHAR(100) NULL,
    locked_at DATETIME NULL,
    UNIQUE KEY uniq_partner_txn_date (corporate_partner, transaction_date)
);

Developer Notes

  • AutoRecon is a PHP + MySQL application intended for XAMPP localhost deployment.
  • Excel parsing and export behavior uses PhpSpreadsheet.
  • Database writes should use prepared statements.
  • AJAX-style operations should return clear JSON endpoint responses.
  • Do not alter stored database values just to make display-only formatting easier.
  • Use pagination, chunking, or virtual scroll for large reconciliation data sets.
  • This documentation folder is static and separate from the main app flow.
  • Do not make PHP controllers, routes, or authentication depend on these documentation files.
